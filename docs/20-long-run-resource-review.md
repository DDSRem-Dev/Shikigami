## 数据和复算方法

- 原证据：`/tmp/shiki-default-rotation-linux-current-20261029/`，日志SHA-256为`c9ece4e46c47689595a8a0f0b8f557cfcd07bbf960660ec7e5f83cb9bfe8a850`；697源manifest SHA-256为`660dc6e93b3ce1300d084f02665a4e9dcf88178d7e6fd044a2ce05d366e7cca2`。
- 完整解析740个checkpoint前的5920条资源记录；每组8个角色，4个常驻角色和4个插件角色，轮换后按新PID区分，合计12个进程代际。全部原始样本、极值和不完整末小时均保留，未滤去高点。
- 每组资源读数是顺序采集，日志没有单次读数时间；只能关联紧随其后的checkpoint时间。小时桶从`observation_started`算起，第13桶仅约半小时，不伪装成完整小时。
- RSS使用MiB（2²⁰字节）；RSS不是存活堆，也不等于泄漏。CPU是同一PID累计user+system之差除以关联checkpoint时间差，100%表示一个逻辑核；不跨PID/代际相减，不当作瞬时CPU峰值。共享页可能重复计入不同进程，不将各进程RSS相加当真实总物理内存。
- 原固定资源门禁只证明checkpoint前预算内连续三次满足FD+4与测试harness goroutine+6，不提供生产goroutine、连续FD/RSS/CPU硬限制或每个瞬时峰值。

分析与完整数据保存在`/tmp/shiki-final-resource-review-20261029/`：`analyze.py`、`all-samples.json`、`all-generations.json`、`all-hours.json`、`source-delta.json`、`runner-build-delta.json`、`source-diff.txt`、`analysis-summary.json`、`verification.json`。单独从原日志复算全部5920行、12代际计数/极值/中位数和全部小时计数/峰值；同PID累计CPU非递减，原终态证据hash保持。临时目录不是永久证据仓库；失去原始数据时不能仅凭本摘要扩大结论。

## 下一步判据

本批完成完整记录分析和当前alpha覆盖差异审查，没有确认新的生产保留根，因此没有修改产品，也没有重复已停止的短窗口内存实验或启动另一轮12小时。

剩余资源结论缺的是生产存活heap/object及生命周期归因，原RSS记录无法补出这些数据。下一次诊断必须先固定一个具体所有权假设、触发操作、可观测保留对象和关闭后结果；只有确定的反例才修改实现，随后做受影响回归。若要取得当前alpha默认时长证据，应作为独立候选验收，明确涵盖新Stop/当前生命周期，并区分未调用的startup、安装和外部登录路径；不能仅凭文件数量变化决定重跑，也不能把启动一次同场景当作解决资源问题。

Homebrew alpha.2自动分发和隔离测试密钥演练已独立完成，结果见21/22；账号、VPS/物理重启、原生平台及物理多设备门槛保持原要求。

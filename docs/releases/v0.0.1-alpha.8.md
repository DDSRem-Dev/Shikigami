# Shikigami v0.0.1-alpha.8

本版本用于下一轮修复后实机测试，不是 beta 或稳定版。本说明随标签冻结；公开状态、固定源码和签名来源以 GitHub Release、Actions 及 PROVENANCE.json 为准。

## 修复

- 同步冲突解决改用有界复合操作预算，默认最多15分钟，不再被普通查询的5秒预算提前截断。显式 `--timeout`（包括5秒）和更早的调用方截止仍优先；单文件传输及元数据预算保持。交互等待每10秒显示进度，JSON输出保持结构化。
- keep-both部分完成后保留已有副本，要求重新观察两端并明确选择方向，阻止未决副本重复或递归复制。不会因一端缺失就自动补写，也不重放结果未知的文件操作。
- 会话创建和同步决策超时提示包含实际 request ID，区分请求尚未发送与结果未知，指导先查状态再决定。会话环境准备跨worker返回的取消/截止错误保持原错误码及持久去重结果。
- 端口转发目标暂时拒绝连接时，仅结束尚未建立的该次TCP连接，保留原本地监听和其它连接；后端恢复后可从同一转发端口建立新连接。仅适用于授权及allowlist检查后确认的loopback ECONNREFUSED；不自动重试或重放数据，其它错误保留原处理。
- 浏览器接管请求绑定确认时的attachment、instance及revision，旧请求不能改绑到重连后的连接；断开时取消旧请求。只有当前连接的匹配流事件授予/撤销控制，HTTP成功或状态快照不能授予权限。
- 浏览器已确认的控制结果不再被迟到HTTP超时提示覆盖；控制撤销后提示同步变为只读。旧状态请求的结束不会占用或释放新连接的刷新槽。

## 安装或升级

以下命令在本版本签名资产公开后可用。两端均需升级，已有身份、配置、项目和浏览器profile保留。

VPS（Debian12 / Ubuntu24.04）：

```bash
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-alpha.8/bootstrap.sh | sudo bash -s -- --quickstart --version=v0.0.1-alpha.8
```

Mac（当前登录用户，不加sudo）：

```bash
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-alpha.8/bootstrap.sh | bash -s -- --quickstart --role=client --version=v0.0.1-alpha.8
```

升级会重建宿主/插件连接，独立tmux与Chrome数据保留。若系统支持升级要求停止Chrome，先保存未提交页面内容并按提示操作；密钥环登记复用，不重置。详见[一键安装指南](https://github.com/DDSRem-Dev/Shikigami/blob/master/docs/28-quickstart.md)。

## 验证与已知边界

修复已有确定性回归、race、真实双worker端口集成及架构检查；查看器18项行为测试通过。固定源完整CI与四目标签名构建由发行流水线执行，结果以实际Actions记录为准。

alpha.7实测已覆盖同步功能、终端保活/配置快照、浏览器中日输入/显式剪贴板/上传下载/双查看器接管；也实际出现端口后端恢复后离线、会话/浏览器间歇超时、同步重试耗尽。alpha.8发布不代表这些现场问题已经全部消失，默认预算、端口恢复和浏览器控制仍须升级后复验。同步重试耗尽后的显式resume成功不等于自然恢复或长期稳定。新会话默认shell交互体验也保留复验项，不能用手工切换Bash的通过代替。

网络专项按用户安排暂跳；真实Claude授权、主观长用、切网/睡眠、完整干净双机首装与物理重启分别保留未验边界，不承诺消除网络损耗。升级两端和后续实测独立于本次公开发布登记。旧标签与签名资产保持不变，许可证GPL-3.0-only。

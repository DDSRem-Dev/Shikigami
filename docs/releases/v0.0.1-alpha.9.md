# Shikigami v0.0.1-alpha.9

本版本修补远程浏览器的兼容性、响应路径和退出诊断，用于升级后的实机复验，不是 beta 或稳定版。本说明随标签冻结；公开状态、固定源码和签名来源以 GitHub Release、Actions 及 PROVENANCE.json 为准。源码及隔离测试通过不表示已经发布，也不表示 Cloudflare 验证或原网络卡顿已经解决。

## 改进与修复

- 新启动默认普通浏览模式 `browse`，不建立 Chrome 原生诊断通道。需要原生浏览器诊断时，使用 `browser start --diagnostics` 显式选择 `diagnostic`。同一 profile、相同模式复用实例；切换模式必须 `--replace-running` 并确认停止旧实例。旧实例保持真实模式，不因升级自动重启或显示成普通浏览。所有新版启动调用均检查 CLI、agent、daemon 与浏览器 worker 的模式能力；旧组件缺少能力时明确失败，不静默忽略模式选项。
- 优化四条响应路径：每帧授权仅复制所需服务器记录，仍即时检查撤权；只读画面请求的慢 socket 写入不再占用全局控制锁；状态查询在等待 runtime/region 时释放 worker 锁，返回前核对期间是否发生变更；控制通知使用独立有界队列，避免与图像数据争用同一队列容量。鼠标、键盘等修改桌面的操作仍按权限和控制 revision 串行校验，RFB 数据不丢弃、不重排、不重放。已在发送中的数据不能被控制通知抢占，持续过慢的连接仍可能被取消。
- 查看器增加 **Smooth / Balanced / Clear** 画质选择，默认 Balanced 保留原设置。Smooth 降低画质并提高压缩以减少流量，Clear 提高画质并可能增加带宽需求；选项只影响当前查看器。新增本机 WebSocket 接收速率与发送缓冲区显示，依赖详情可折叠。这些数值不是 RTT 或远端画面延迟测量，不能据此认定网络已恢复。
- 区分 Chrome 正常退出与异常退出：正常关闭最后窗口、进程退出码为 0 时显示 `stopped`；异常退出报告固定组件名称及实际退出码或信号，不再统一显示为未知依赖崩溃。异常仍需人工处理，不自动循环重启。普通浏览模式通过真实 Chrome 窗口的 PID 和窗口类别检查就绪，修复官方 Chrome 窗口名称包含 profile 路径时的误判。
- 保留 alpha.8 的 `profiles.json` 磁盘字段形状，避免新增模式字段使旧版本严格读取失败。模式保存在独立、不可变的启动记录，重新加载时核对身份和完整启动配置；新记录缺少模式、损坏或不一致时明确拒绝。保存失败恢复及请求去重保留真实模式。本地旧格式读写和再次升级回归不等于已完成正式版本回滚验收。
- Linux 浏览器系统支持新增发行版 `x11-utils` 依赖，供普通浏览模式检查窗口就绪；仍使用官方 Chrome、普通用户、Chrome sandbox 和已登记的加密密钥环。

## 安装或升级

以下命令仅在本版本签名资产公开后可用。**Mac、VPS 应用及 VPS 的 root 管理浏览器 runtime 均需升级**；只更新 CLI 或插件不能完成本次更新。完整 quickstart 会检查并更新系统支持，已有身份、配置、项目、浏览器 profile 和密钥环登记保留。

升级已有浏览器环境时，先保存网页中未提交的内容，再从 Mac 显式停止受管 Chrome。下方 `my-vps` 和 `work` 应替换为实际保存的服务器名称与 profile ID；关闭查看器页面不等于停止 Chrome。

```bash
shiki --server my-vps browser stop work --yes
```

确认停止成功后，在 VPS（Debian12 / Ubuntu24.04）执行：

```bash
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-alpha.9/bootstrap.sh | sudo bash -s -- --quickstart --version=v0.0.1-alpha.9
```

Mac 使用当前登录用户执行，不加 sudo：

```bash
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-alpha.9/bootstrap.sh | bash -s -- --quickstart --role=client --version=v0.0.1-alpha.9
```

按向导复用已保存连接和配置。系统支持更新必须在受管 Chrome 已停止且没有待启动任务时进行；若安装器报告仍在运行，应完成显式停止后重试，不强行替换 runtime。升级会重建宿主/插件连接，独立 tmux 与 Chrome profile 数据保留；不保证停止前未保存页面内容恢复。密钥环登记复用，不重置。完整流程见[一键安装指南](https://github.com/DDSRem-Dev/Shikigami/blob/master/docs/28-quickstart.md)。

两端完成升级后，若向导尚未启动浏览器，可在 Mac 启动普通浏览并打开查看器：

```bash
shiki --server my-vps browser start work --yes
shiki --server my-vps browser status work
shiki --server my-vps browser open work --read-only=false --launch
```

检查状态中的实际 `mode` 为 `browse`，查看器中点击 **Take control** 并等待控制权确认。原生诊断仅在明确需要时启用，它可能影响网站兼容性；切换会停止当前实例：

```bash
shiki --server my-vps browser start work --diagnostics --replace-running --yes
shiki --server my-vps browser diagnose work
# 完成诊断后，显式重启回普通浏览：
shiki --server my-vps browser start work --replace-running --yes
```

普通浏览实例拒绝原生诊断请求。诊断默认不访问外部供应商，外部检查仍须单独授权；模式切换不修改出口、代理、DNS 或浏览器指纹，也不代替用户完成网站验证与账号登录。

## 验证与已知边界

本地已通过受影响 Mac 包的 race、普通 UID Linux arm64 的 runtime/server/安装及真实 daemon 跨进程测试、架构检查、静态检查、协议生成一致性和查看器 24 项行为测试。持久格式兼容与窗口识别后续补修另有冻结源码的 Linux race 回归，路径与模式证据异常另有负向测试。授权函数基准只证明局部复制开销下降，不代表端到端浏览器提速比例。固定标签源码的完整 CI、四目标签名构建和公开资产来源以实际发行流水线结果为准。

隔离 Linux arm64 普通用户环境使用官方 Chrome 158.0.8127.36，保留 sandbox 和加密测试密钥环，实际验证普通浏览窗口就绪、原生诊断拒绝，以及显式诊断实例的真实诊断结果；正常退出状态也已验证。测试采用禁网容器与合成页面，未使用真实账号，不能替代完整 systemd 安装、两端 Shikigami 链路或公网网站验收。

alpha.8 用户实测仍出现卡顿及 Cloudflare 挑战循环。本版解决已确认的代码瓶颈并提供普通浏览模式，但未确证挑战循环的单一原因，不承诺 Cloudflare 放行或消除网络延迟。正式升级后仍需用户在原网络上人工复验挑战、输入响应和持续使用体验；真实 Claude 授权、切网/睡眠、长稳、完整干净双机首装及物理重启分别保留未验边界。公开发行、两端升级与这些外部验收独立记录，不以其中一项通过替代其它门槛。

# Shikigami v0.0.1-beta.1 — 首个公开 Beta 发布说明

本版本为 Shikigami 首个公开 Beta 预发布（`v0.0.1-beta.1`）。本说明随标签冻结；公开状态、固定源码提交和签名来源以 GitHub Release、Actions 运行记录及 `PROVENANCE.json` 为准。源码与候选检查通过不等同于全部外部环境已复验，实际支持范围与保留边界见下文及 `docs/18-release-readiness.md`。

## 本版重点改进与修复

- **默认交互 shell 智能选择（修复 Debian/Ubuntu `/bin/sh` 方向键缺陷）：** 新增纯 Go 登录 shell 解析（兼容 `CGO_ENABLED=0` 静态构建），严格校验 `/etc/passwd` 与 `/etc/shells` 中的常规可执行文件，保留用户显式配置的 `zsh`、`fish` 等交互 shell；当系统账户默认 shell 为 `/bin/sh` 或 `/bin/dash` 且存在可用的 `/bin/bash` 时自动升级为 `/bin/bash`，消除 `--no-claude` 会话及 `StopClaude` 回退 shell 中方向键输出原始转义序列（`^[[D`）无法行内编辑的问题。
- **Claude Code 默认启用全屏无闪烁 TUI 模式（`CLAUDE_CODE_NO_FLICKER=1`）：** 受管 `tmux` 会话在创建（`Create`）与进程重拉起（`Respawn` / `RespawnDead`）时默认注入 `CLAUDE_CODE_NO_FLICKER=1`（管理员若在 daemon 环境显式配置 `CLAUDE_CODE_NO_FLICKER=0` 等值则原样保留），使远端 Claude Code 直接进入 alternate-screen 全屏渲染模式：输入框固定在终端最底行、占满完整终端高度、支持鼠标滚轮事件透传，并消除 `tmux` 下流式输出的视口跳动与闪烁；即使 daemon 升级时复用旧受管 `tmux` server，新建或显式重启的会话也会立即生效。
- **汇总 alpha.1–alpha.10 核心与四插件基线：** 包含 Connect/protobuf over HTTP/2 传输、内嵌 `tsnet` 与可选直连 TLS、多观察者与显式版本化终端控制权、项目级共同基线双向文件同步（`sync`）、loopback TCP 转发与后端拒绝监听保持（`port`）、Linux 地区环境受限 helper 与 DNS 恢复守卫（`region`）、远程持久化 Chrome 普通浏览/诊断双模式与默认 **Smooth** 画质 noVNC 1.7.0 查看器及本地传输观测指标（`browser`），以及第三方插件签名 marketplace 安装与更新。

## 安装或升级

以下命令在本版本 23 个签名资产公开后可用。从旧版升级已有远程浏览器环境前，先保存网页中未提交内容并显式停止受管 Chrome（`my-vps` 与 `work` 替换为实际服务器标签和 profile ID；关闭本地查看器页面不等于停止远端 Chrome）：

```bash
shiki --server my-vps browser stop work --yes
```

随后在 VPS 与 Mac 分别执行固定版本一键安装/升级向导：

```bash
# VPS（Debian 12 / Ubuntu 24.04）
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-beta.1/bootstrap.sh | sudo bash -s -- --quickstart --version=v0.0.1-beta.1

# Mac（当前登录用户，不加 sudo）
curl --proto '=https' --proto-redir '=https' -fsSL https://github.com/DDSRem-Dev/Shikigami/releases/download/v0.0.1-beta.1/bootstrap.sh | bash -s -- --quickstart --role=client --version=v0.0.1-beta.1
```

向导先用预置公钥验证 Ed25519 归档签名与 `SHA256SUMS` pin，再执行包内 `shiki-install`，原有节点身份、连接凭据、项目、浏览器 profile 和加密密钥环保持不变。完整说明与恢复流程见[一键安装指南](https://github.com/DDSRem-Dev/Shikigami/blob/master/docs/28-quickstart.md)。

也可通过 Homebrew 安装或更新 CLI 与认证 bundle（包管理器本身不自动重启或升级已注册的后台服务，需按 `brew info` caveats 显式执行服务升级）：

```bash
brew tap ddsrem-dev/shikigami https://github.com/DDSRem-Dev/Shikigami
brew install ddsrem-dev/shikigami/shikigami
```

升级完成后，旧有已运行的 `tmux` 会话不会自动被杀死；若需让升级前已存在的 Claude 会话切换至全屏 TUI 模式，可在会话内执行 `/tui fullscreen` 或运行 `shiki --server my-vps --project <项目> sessions restart <会话>`（重启不会回滚项目文件，但不承诺自动恢复对话上下文）。

## 验证范围与已知边界

- **发布前实机与自动化验收：** 基于已部署签名 `alpha.10`（Mac `darwin/arm64` + Debian 12 `linux/amd64` VPS）已完成跨日 `RECONNECT_EXHAUSTED` 显式恢复、终端 detach/reattach 保活与配置快照恢复、真实 Claude Code 官方登录授权（经远程 `work` Chrome 完成）与文件写入任务、`sync` 初始冲突/双向同步/暂停/`keep-both`/重命名/删除（含跨越 5 秒的多步冲突解决）、`port` 转发与后端拒绝同端口恢复、`region` 检查与零变更计划、`browser` 默认 Smooth 日常浏览体验及断网/睡眠恢复确认。本版两项终端修复已通过 macOS、Debian 12 容器、16 项 VT 终端语义及全套集成/故障 race 回归。
- **保留边界（不超范围承诺）：** 本版本仍为 `0.0.x` Beta 预发布，不承诺固定帧率或网络延迟 SLA；弱网/跨国 Tailscale 链路上短查询偶发 5 秒 `deadline_exceeded` 仍可能出现，遇到 `RECONNECT_EXHAUSTED` 可用 `shiki connect <server>` 恢复，冲突解决超时应先核查 `sync status` / `sync conflicts` 与两端文件。全新双机从零运行新版 quickstart 首装、VPS/Mac 物理主机重启自动解锁恢复、原生 Windows（非 WSL2）、GUI、多租户隔离、文件级快照/三方自动合并及外部第三方插件市场目录互操作仍属于未实测或未纳入本版范围的事项。
